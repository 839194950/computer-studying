## 1. 这是什么，为什么做

一个**教计算机与编程知识的网页**，核心不是"读完一篇文章"，而是"**真的把知识点记住**"。

学编程的人普遍的问题不是找不到资料，而是看过的资料留不下：今天看懂了指针，两周后写代码还是懵。菜鸟教程这类站点解决的是"查得到"，但没有解决"记得住"。这个网站把每个知识点切成一张卡片，用类似背单词的间隔重复机制反复找你，让"我看过"变成"我会"。

它同时服务两个目的：

1. **自己用**：把学到的软硬件、语言、系统、安全知识固定下来，随时能看到"我到底记牢了多少"。
2. **给别人用**：做成一个能上线、能拿出去讲的作品。

## 2. 目标 / 非目标 / 反目标

**目标**

- 手机和电脑上都能随时打开，两分钟就能学完一次。
- 学习过程本身有快感：动效流畅、反馈即时，像在玩而不是在啃书。
- 每个知识点都有明确的"复习到期时间"，网站替用户安排，不靠自觉。
- 长期可见的掌握度数据：哪些记牢了、哪些在漏水。
- 内容覆盖面最终包括计算机基础、软硬件原理、主流编程语言、操作系统、网络与网络安全。

**非目标（第一版明确不做）**

- 不做代码在线运行沙箱。
- 不做账号系统与云同步（数据先存在本机，后续版本再加）。
- 不做社区、评论、UGC 投稿。
- 不做视频课程、不做长篇教程正文。
- 不做排行榜、竞技对战。
- 不做 AI 自动生成卡片（内容先由我们人工写定）。

**反目标（做成了也算失败）**

- 变成一个"内容很多但没人复习"的资料站。
- 动效堆到卡顿、手机发烫，反而让人不想打开。
- 为了游戏化而游戏化：金币、皮肤、抽卡盖过学习本身。
- 卡片内容变成名词解释背诵，脱离"这个知识解决什么问题"。

## 3. 约束

- **先网页，后手机**：第一版是 Web；架构必须让"装到手机上"是增量工作而不是重写。做法：响应式 + PWA（可添加到桌面、可离线）+ 无浏览器专属依赖，将来用 Capacitor 打包。
- **无后端**：数据存浏览器本地（IndexedDB）。所有学习记录必须可导出/导入 JSON，防止换设备丢数据。
- **内容可审校**：卡片内容以静态 TypeScript 数据文件形式存在仓库里，方便逐条修改，不走数据库。
- **中文界面**。
- **可交接**：仓库内维护 `README.md`（怎么跑、目录结构）与 `docs/PROGRESS.md`（进度日志、关键决策、下一步）。任何一次中断后，新人或新会话只读这两份文件就能接手。
- 内容参考菜鸟教程（runoob.com）的知识分类与覆盖范围，但**文字自行撰写**，不复制原文。

## 4. 视觉方向（已确认：糖果街机）

风格关键词：高饱和、粗描边（3–4px 深墨色）、厚投影（偏移 4–6px 的实心阴影，无模糊）、大圆角（14–22px）、贴纸感。

### 4.1 色板

| 用途 | 色值 |
|---|---|
| 墨色（描边/正文） | `#241A3D` |
| 纸张底色 | `#FFF8EE` |
| 主色 · 紫 | `#7B5CFF` |
| 正确/掌握 · 薄荷 | `#2ECC8F` |
| 强调/提醒 · 黄 | `#FFD23F` |
| 危险/遗忘 · 粉 | `#FF7AB5` |
| 信息 · 天蓝 | `#5AD2FF` |
| 次要文字 | `#8B85A6` |
| 卡片白 | `#FFFFFF` |

### 4.2 字体

- 正文与标题：系统无衬线（PingFang SC / 思源黑体 / Inter），标题字重 800–900。
- 地址、代码、计数：等宽（ui-monospace / JetBrains Mono）。

### 4.3 插画

- 全部为**手写 SVG**（可缩放、可逐元素动画、无外部图片依赖）。
- 统一规范：描边 `#241A3D` 3px、圆头线帽、平涂填充、不加渐变（极少数高光例外）。
- **吉祥物「小芯」**：一块带天线和眼睛的拟人芯片，担任讲解员。状态：待机（轻微呼吸浮动）、开心（答对时弹跳）、困惑（答错时歪头）、睡觉（今日已完成时）。
- 每张知识卡配一张**概念示意插画**（如"内存格子 + 指针箭头"），用同一套粗描边语言，支持逐段入场动画（先画格子，再长箭头，最后高亮目标）。

### 4.4 动效原则

- 时长 150–350ms，缓动 `spring` 或 `ease-out`，不做缓慢的大位移。
- 每个交互只允许一个"主角动效"（如答对时的星星炸开），其余元素轻微跟随，避免满屏乱动。
- 尊重 `prefers-reduced-motion`，开启无障碍设置时降级为淡入淡出。
- 目标：60fps；只动 transform / opacity。

## 5. 页面结构

移动优先，桌面端最大内容宽 720–880px，居中单栏；桌面端章节地图可两栏。

### 5.1 学习台（首页）

- 顶部：连胜天数、今日已复习数。
- 中央：掌握度环（百分比 + "记牢了 N / 共 M 张"）。
- 主按钮：**开始今天的复习**（显示到期张数）。若今日已清空，显示小芯睡觉状态 + "今天没事了"。
- 下方：四条主线的迷你进度条。
- 底部导航（移动端）：学习 / 地图 / 图谱 / 我。

### 5.2 章节地图

四条主线，每条线上按关卡排列（节点串联，像路径）：

1. **硬件与原理** — 计算机怎么跑起来
2. **编程语言** — 变量、类型、函数、指针、内存
3. **操作系统** — 进程、线程、内存管理、文件、权限
4. **网络安全** — 密码学、Web 攻击面、协议安全、防护

节点状态：未解锁（灰）/ 学习中（黄）/ 已通关（薄荷 + 对勾）。通关条件 = 该章全部卡片达到"记牢"档。

解锁规则：四条主线**互相独立**，各自第一章默认开放；同一条主线内按顺序解锁（前一章通关后开下一章）。跨主线随时可切换，不要求按固定顺序学。

### 5.3 卡片页（学习与复习共用）

两段式：

1. **讲解面**：插画 + 一句话解释 + "懂了，考考我"。
2. **问题面**：一道单选题（4 选 1）+ 提交后展开解释。

反馈动画：答对 → 卡片翻转收起、薄荷色星星从中心炸开、进度环长一节；答错 → 卡片横向抖动、正确项描边点亮、该卡退回上一档并在当日稍后再出现。

### 5.4 记忆图谱

- 顶部：掌握度环 + 四色图例（记牢了 / 刚学会 / 快忘了 / 没学过）。
- 堆叠条：全部卡片按状态切分，一格代表一张卡。
- 按主线分组的列表：每条线下钻到具体卡片，显示下次复习时间。
- 底部：近 30 天掌握度折线（数据来自每日快照）。

四色由两个条件实时派生，不额外存状态：

| 颜色 | 判定 |
|---|---|
| 没学过（紫灰） | 没有任何进度记录 |
| 快忘了（粉） | 已过期，即 `dueAt < 现在` |
| 记牢了（薄荷） | 未过期且档位 ≥ 4 |
| 刚学会（黄） | 未过期且档位 ≤ 3 |

### 5.5 我的

设置（每日新卡上限、动效强度、清空数据）、数据导出/导入 JSON、关于。

## 6. 复习机制

**盒式间隔重复（Leitner 变体）**，5 档：

| 档位 | 答对后下次复习 | 含义 |
|---|---|---|
| 1 | 1 天后 | 刚学会 |
| 2 | 3 天后 | |
| 3 | 7 天后 | |
| 4 | 21 天后 | 记牢了 |
| 5 | 60 天后 | 记牢了 |

- 答对：档位 +1（最高 5），按新档位设置 `dueAt`。
- 答错：档位 −1（最低 1），`dueAt` = 当天稍后（本轮队列末尾），当日必须再过一次。
- 新卡：首次学习后进入档位 1。
- 每日上限：到期卡全部要做；新卡默认 10 张/天（可设置）。
- 连胜：当天完成所有到期卡（且至少 1 张）记 1 天；中断则归零，但保留历史最长记录（不做惩罚动画）。
- 掌握度 = Σ(档位权重) / 总卡数，权重 1→0.1、2→0.25、3→0.5、4→0.8、5→1.0；"记牢了"= 档位 ≥ 4。

### 6.1 每日队列怎么组

- 队列 = 全部已到期卡（`dueAt <= 今天 00:00`）+ 最多 N 张新卡（默认 10）。
- 到期卡永远排在新卡前面。
- 新卡按主线轮转选取：优先补四条线里进度最低的那条，章内按卡片顺序取，且只从已解锁章节里取。

### 6.2 日期的算法

- 一律按**设备本地时区**的自然日算，`dayKey()` 返回 `YYYY-MM-DD`。
- "1 天后"= 下一个自然日，不是 `now + 24h`。否则晚上 22 点学的卡，第二天白天打开会显示"今天没事了"，连胜直接断。
- `dueAt` 存目标日 00:00 的时间戳；判断到期用"`dueAt` 早于今天 00:00"。

### 6.3 答错之后

- 答错的卡插回**本轮队列末尾**，`dueAt` 设为当前时刻（立即重新到期）—— 关掉页面当天再打开，它仍在今日队列里。
- 同一张卡在一轮内连续答错 2 次，本轮不再出现，标注"今天先放过你"，明天继续（避免死循环）。
- "今日完成"= 队列清空（答错的卡满足上述终止条件也算清空）。
- "今日已复习"按**卡片去重**计数。

### 6.4 连胜口径

当天把队列清完就记 1 天，**新卡也算**（新用户头几天没有到期卡，否则永远开不了连胜）。当天一张没做则清零。

## 7. 数据模型

```ts
type TrackId = 'hardware' | 'language' | 'os' | 'security';

interface Card {
  id: string;              // e.g. 'mem-pointer-01'
  track: TrackId;
  chapter: string;         // 章节 id
  title: string;           // 问题标题
  illustration: string;    // 插画组件 key
  explain: string;         // 讲解面一句话（≤ 40 字）
  question: string;
  options: string[];       // 4 项
  answerIndex: number;
  explanation: string;     // 答后解释（1–3 句）
}

interface CardProgress {
  cardId: string;
  box: 1 | 2 | 3 | 4 | 5;
  dueAt: number;           // 时间戳
  lastReviewedAt: number | null;
  lapses: number;          // 答错次数
}

interface DailySnapshot {
  date: string;            // 'YYYY-MM-DD'
  mastery: number;         // 当日结束时掌握度（0–100）
  reviewed: number;        // 当日复习卡片数（去重）
}

interface AppState {
  progress: Record<string, CardProgress>;
  streak: { current: number; longest: number; lastActiveDate: string | null };
  snapshots: DailySnapshot[];   // 每日快照，保留 365 天，超出裁掉最早的
  settings: { newCardsPerDay: number; reducedMotion: boolean };
  version: number;
}
```

存储：IndexedDB（库 `memory-chip`，store `state`，单条记录），启动时水合，变更后节流写回。导出为单个 JSON。

导入策略：**整包覆盖**。导入前先把当前数据自动导出成备份文件，并在确认弹窗里说清"将导入 X 张卡片进度，覆盖本地 Y 张"；`version` 不匹配则提示并拒绝（V1 只有版本 1）。不做合并 —— 合并冲突策略的复杂度和出错成本都高于它带来的便利。

## 8. 技术方案

- **构建**：Vite + React 18 + TypeScript
- **样式**：Tailwind CSS（自定义色板与阴影 token）
- **动画**：Framer Motion
- **路由**：react-router
- **状态**：zustand（轻量，配合持久化中间件写 IndexedDB）
- **PWA**：vite-plugin-pwa（manifest + 离线缓存 + 图标）
- **测试**：Vitest，重点覆盖间隔算法、掌握度计算、连胜判定
- **部署**：纯静态产物（`dist/`），可放任意静态托管

目录结构（建议）：

```
src/
  app/            路由与布局
  components/     UI 基件（按钮、卡片、进度环、底部导航）
  illustrations/  小芯与概念插画 SVG 组件
  features/
    study/        今日队列、卡片页
    map/          章节地图
    stats/        图谱与统计
    settings/
  content/        知识卡数据（按 track 分文件）
  lib/            间隔算法、进度计算、存储
```

## 9. 内容规划（首批 80 张）

参照菜鸟教程的分类维度（计算机基础 / 编程语言 / 前端 / 后端 / 数据库 / 运维 / 网络安全），收敛为四条主线，每条 5 章 × 4 卡：

**硬件与原理**：计算机组成（CPU/内存/磁盘）、二进制与编码、编译与解释、网络分层、性能与并发基础

**编程语言**：变量与类型、函数与作用域、指针与引用、数据结构入门、常见语言对比（C / Python / JS 的心智模型差异）

**操作系统**：进程与线程、内存管理、文件系统、权限与用户、命令行与进程观察

**网络安全**：密码学基础（哈希/对称/非对称）、Web 攻击面（注入/XSS/CSRF）、传输与证书、认证与授权、常见防护与日志

写作要求：每张卡只讲**一个**点；讲解面一句话必须给出"它解决什么问题"；选项的错误项要是**常见误解**，不能是凑数的废话。

内容由我方撰写（80 张），以静态 TS 文件提交，用户按主线逐条审校。流程：先出**每线 2 张样板卡**（共 8 张）确认写法与语气，确认后再批量写完剩余 72 张。涉及事实正确性的部分（指针、内存管理、密码学、Web 攻击）逐条自查，写不确定的就不写。

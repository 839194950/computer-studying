## 评审与修复（2026-11-04）

独立评审提了 2 个 Critical、4 个 Important。处理如下：

### 已修（都有先失败后通过的测试）

- **C1 新卡首答跳空三天**：`review()` 改为第一次答对停在第 1 档（第二天复习），之后才逐档上升。原先新卡答对直接进第 2 档 = 3 天后，导致第二天、第三天打开都是"今天没事了"，连胜永远断开。
- **C2 断签不清零只写在磁盘上**：首页与结算页渲染时调用 `resolveStreak`，界面立刻显示 0。
- **I2 导入没有确认与备份，文案却说有**：改成两步（选文件 → 预览"将导入 X 张 / 覆盖本地 Y 张" → 确认后才写库），确认时先自动下载备份；`parseState` 增加对每条进度记录的字段校验（`box` 必须是 1–5、`dueAt` 必须是有限数字、`cardId` 必须是字符串）。
- **I3 答错的卡永远滞留在今日队列**：同一张卡当天答错 2 次后，`dueAt` 排到明天零点，首页才可能真正出现"今天没事了"。

### 裁定不改

- **I1 首发有 3 张卡被章节锁挡着**（指针、字节、XSS）：章节锁是设计要求（前一章全部记牢才解锁下一章），不是缺陷。代价：首发只有 5 张卡能立刻学，其余约第 10 天随解锁出现。已写入 README。
- **I4 IndexedDB 读写失败仍静默**：无痕模式或配额写满时会丢进度，没有错误提示。代价：用户可能不知道数据没存上；缓解手段是设置页的手动导出。留到 V2 加检测与横幅。
- **`<Link>` 包 `<Button>`** 产生的 `<a><button>` 嵌套：保留现状，等设计系统重构时一起处理。

## 内容与图解扩建（2026-11-05）

目标：把 8 张样板卡补到 80 张，并让每个知识点都有贴切的图，讲解从"一张静态图"变成"一步步点亮"。

### 做了什么

- **模型**：`Card` 新增 `steps: TeachStep[]`（`caption` + `focus`），每张卡 2–4 步。
- **图解系统**：新增 `src/illustrations/base.tsx`，提供 `Part`（按 focus 淡出未聚焦部分）、`Label`、`Box`、`Arrow`、`Defines` 与统一色板。
- **20 张章节概念图**：每章一张总览图，含 4 个语义化图元，正好对应本章 4 张卡。命名 `*Diagram.tsx`，各自导出 `*_PARTS`。
- **registry 改造**：从 `Record<string, Component>` 改为 `Record<string, { Component, parts }>`，新增 `getDiagramParts` / `hasIllustration` / `ILLUSTRATION_KEYS`。
- **讲解面**：StudyPage 讲解阶段按 steps 推进，图中只亮当前部分，配旁白 + 步骤点 + `1/3` 计数，最后一步才变成"懂了，考考我"。带 `aria-live="polite"` 播报旁白。
- **内容**：四条主线各 20 张，共 80 张；每章 4 张。原有 8 张卡的 id 全部保留（进度数据兼容），只补 `steps` 并换用新图。

### 关键决策

- **一章一图，四元聚焦**：不给 80 张卡各画一张图（重复且难维护），而是每章画一张"知识地图"，章内 4 张卡分别点亮不同区块。好处是 4 张卡之间形成结构关系，复习时能回忆"这张图里它在哪一块"。
- **focus 强制校验**：`content.test.ts` 检查每张卡 `steps[].focus` 必须是该插画 `parts` 的子集，写错图元 id 直接测试失败，避免高亮静默失效。
- **`Part` 用 style 而非属性控制 opacity**：SVG 属性变化不触发 CSS transition，用 `style` 才能得到 240ms 淡出过渡。
- **删除旧插画**（`Pointer/Binary/Process/Hash`）：内容全部改指向新图，旧文件无引用后移除，避免两套图并存。
- **截图核对**：临时加 `__gallery` 路由 + Playwright 把 20 张图渲染出来逐张看，修掉了缺页两行重叠、证书标签出画布、越权弧线穿框、闭包说明压边框等排版问题，完成后删除临时页与脚本。

### 测试

- `npm test`：15 文件 / **61 用例全绿**。新增用例覆盖：80 张总量、每章 4 张、steps 至少两步且旁白 ≤ 44 字、插画 key 已注册、focus 图元真实存在、每个图能带 focus 渲染。
- `npm run build` 通过。

## 图谱页卡片下钻（2026-11-06）

**问题**：设计文档 5.4 要求「按主线分组、下钻到具体卡片、显示下次复习时间」，但 `/stats` 的「按主线看」只有 `learned/total` 和一个最近到期日，看不到 80 张卡各自的状态。

**做了什么**：
- 每条主线变成一个可折叠区块：标题行按钮（主线名 + 已记牢数 + 展开箭头）+ 一句到期提示，展开后列出该线全部 20 张卡。
- `CardRow`（`src/features/stats/CardRow.tsx`）：状态色点 + 卡片标题 + 下次复习日（`11 月 9 日`），没学过写「还没开始」。为后续错题本列表预留复用。
- `pickFocusTrack`（`src/lib/stats.ts`）：默认展开哪条线的纯函数，优先级 forgotten → learning → new，同档比卡数，全都没学过时取第一条。
- `src/features/stats/statusStyle.ts`：四色的唯一来源，图例、堆叠条、卡片行共用，避免第二套色板。
- `src/features/stats/foldState.ts`：展开状态存模块级变量（`undefined` 未选过 / `null` 全收起）。切页保持，刷新回默认，不进 `useStore`、不进导入导出 JSON。
- `formatMonthDay` 挪到 `src/lib/time.ts`，图谱页两处日期格式统一。

**关键决策**：
- **折叠状态不写持久化**：它是视图状态，混进学习进度会让导出文件、`parseState` 校验跟着变复杂，收益不值。
- **只读不跳转**：卡片行不做成链接，图谱页只负责「看状态」，学习入口仍走首页 / 章节地图。
- **不用原生 `<details>`**：需要「同时只展开一条」和跨挂载恢复，受控 `button + aria-expanded/aria-controls` 更直接，懒加载列表也更省事。

**测试**：84 → **91 用例全绿**。新增：`pickFocusTrack` 四级优先级与空输入；默认只展开一条；展开后 20 行且状态/日期正确；换线自动收起、再点全部收起；重挂载后展开状态保留。

**下一步**：P1-2 首页四条主线可点，然后只剩内容审校。

## 首页主线入口（2026-11-06）

**问题**：首页「四条主线」看起来像能点（有进度条和大数字），实际是死卡片，点不动；这一区是设计文档里的导航入口。

**做了什么**：
- 每张主线卡包一层 `<Link to="/map">`，与薄弱卡入口、章节节点的做法一致。
- hover 反馈复用章节节点那套：抬升 3px、浅紫底（`bg-brand/[0.06]`）、阴影 `pop → pop-lg`。
- 按下时给位移 + 去阴影，跟章节节点的手感统一；focus-visible 用品牌色 ring，键盘可达。

**关键决策**：
- **不做自动定位**：点进去就是地图顶部，不传锚点参数。定位收益小，但要多维护一套滚动逻辑。
- **一条线一个链接指向同一页**：暂不做「进入即筛该线队列」，地图页本身已经按主线分区，再多一层参数只会让返回路径变复杂。

**测试**：91 → **92 用例全绿**。新增一条：四条主线各自是可点的 `/map` 链接。

## 保存失败可见化（2026-11-06）

**问题**：zustand 的 persist 会吞掉存储层异常。无痕模式、配额写满、浏览器拒绝写入时，界面一切正常，用户以为存上了，其实这次学习全丢——这是首发就留下的已知技术债，唯一缓解手段是设置页手动导出。

**做了什么**：
- `src/store/persistence.ts`：写盘结果的唯一出口。`attemptSave` 包住一次写入，失败不抛错（persist 不需要知道），而是记下 `ok: false` 并广播；同时留住失败的那份数据，`retrySave` 可原样重放。
- `useStore.ts` 抽出 `persistToDisk`（IndexedDB 优先、回落 localStorage），storage 适配器的 `setItem` 改走 `attemptSave`，并在模块加载时 `registerWriter(persistToDisk)`，让「重试」复用的是同一条真实链路。
- `src/components/SaveNotice.tsx`：`role="alert"` 的常驻卡片，只在失败时出现。文案点明原因（无痕 / 空间满）和后果（会丢），给「重试」与「去导出」两个动作。挂在 `App` 里，所有页面都覆盖。
- 位置用 `fixed` 右下角（移动端抬到底部导航上方），不挤压布局，也不和 `TopNav` / `BottomNav` 抢 `sticky` 位置。

**关键决策**：
- **只报错，不报喜**：答对一题就闪「已保存」会打断答题节奏，且正常情况本就没有信息量。用户真正需要知道的是「什么时候没存上」。
- **重试是重放真实写盘，不是重置标志位**：失败时留住 `{name, value}`，重试调同一个 writer，成功后 `pending` 清空，避免把旧数据又写回去。
- **失败不向 persist 抛错**：抛出去只会变成未处理 rejection，控制台红字，界面依旧无感知；状态改由 `useSyncExternalStore` 驱动。
- **「去导出」用 `useNavigate` + `Button`**，不用 `<Link>` 包 `<Button>`，不扩大已有的 `<a><button>` 嵌套债。

**已知边界**：`removeItem`（清空数据）失败仍未上报；只影响「删不掉」，不会丢进度，暂不处理。

**测试**：92 → **103 用例全绿**。新增：写盘成功/失败的状态迁移与订阅广播、重试重放原数据、无失败记录时不碰磁盘、成功写入清掉旧快照、IndexedDB 失败被记成未保存、无 IndexedDB 时回落 localStorage、提示组件三态（正常不渲染 / 失败出现 / 重试后消失）、App 级集成（失败时全站浮出警告）。

## 按钮与链接拆分（2026-11-06）

**问题**：5 处入口写成 `<Link><Button>…</Button></Link>`，渲染出来是 `<a><button>`。读屏会把它当成两个控件（"链接，按钮"），Tab 焦点也会在同一块停两次；这是首发就记下的最后一条技术债。

**做了什么**：
- `Button.tsx` 抽出 `buttonClasses({ variant, size, full, className })`，按钮外观的唯一来源；`Button` 仍是 `<button>`，顺带补了 `focus-visible` ring。
- 新增 `ButtonLink.tsx`：语义是导航就渲染 `<Link>`，套用同一套按钮外观，不存在第二层控件。
- 替换 5 处：首页「开始今天的复习」，学习页空态的「再练一遍 / 回章节地图 / 回地图 / 去图谱看看」。
- 保存提示的「去导出」上一轮已用 `useNavigate`，没有新坑。

**关键决策**：
- **不引入 `as` 多态 prop**：`<Button as={Link}>` 这类写法会让 `Button` 的 props 类型迅速变复杂。单独一个 `ButtonLink` 更直白，也更容易测。
- **`full` 不再必需**：原来靠外层 `<Link className="flex-1">` 撑满，现在直接把 `flex-1` 传给 `ButtonLink`，DOM 少一层。

**测试**：103 → **104 用例全绿**。新增 `ButtonLink` 只渲染一个链接、不含 `button`；首页与学习页空态各补一条「入口里不再有 button」的断言，防止以后又写回嵌套。

## 首页介绍（2026-11-06）

**问题**：打开就是「今天有 N 张卡在等你」，第一次来的人不知道这是什么、也不知道卡片怎么用；产品定位只写在页面角落一行小字里。

**做了什么**：
- 首页标题下方加一块常驻介绍卡（`tone="paper"`）：小芯 + 「这是什么」+ 一句定位，下面三步用法（看懂一张图 / 选一个答案 / 到点再见一次），底部一行覆盖范围「四条主线 · 80 张卡：…」。
- 覆盖范围从 `ALL_CARDS.length` 与 `TRACKS` 派生，扩容后文案自动跟着变，不用改字。
- 顶部原来那句 tagline「把计算机知识真正记住。」删掉，避免和介绍卡重复。
- 三步在手机上竖排、`sm` 以上三列。

**关键决策**：
- **每次打开都显示**（按你的要求）：不做「只给新人看、之后收起」。代价是老用户每天要划过一次，收益是产品定位始终在那儿。
- **放在掌握度环之前**：先解释是什么，再给数据；队列入口仍在介绍之下，不抢首屏第一眼。
- **不是营销页**：没有截图、没有标语堆叠，只有三步用法。这是一块说明，不是落地页。

**测试**：104 → **106 用例全绿**。新增：介绍标题在复习入口之前、三步文案都在、覆盖范围随卡片数生成；以及「今天没事了」时介绍仍在。

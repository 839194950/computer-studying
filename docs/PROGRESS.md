## 任务记录

### Task 1: 脚手架与视觉令牌 — 2026-11-04
- 关键决策：不用 `npm create vite`（目录非空会交互卡住），手写脚手架；`package.json` 名固定 `memory-chip`（中文目录名会被 npm 判非法）；jsdom 固定 25（最新版与 vitest 4 有 ESM 冲突）。

### Task 2: 时间工具
- 全部用本地 `new Date(y, m, d)`，禁 `toISOString()`，避免 UTC 串日。

### Task 3: 间隔算法
- 答对 → 档位 +1，按**新档位**的间隔排期（第 1 档 1 天…第 5 档 60 天）；答错 → 降一档、`dueAt = now` 立即重到期。

### Task 4: 掌握度 / 状态 / 连胜
- 权重 1:0.1、2:0.25、3:0.5、4:0.8、5:1.0；"记牢了"= 档位 ≥ 4。
- 四色：无进度=没学过；已过期=快忘了；未过期且 ≥4=记牢了；其余=刚学会。

### Task 5: 内容模型 + 8 张样板卡
- 四条主线 × 5 章；每卡 `explain` ≤ 40 字，干扰项必须是常见误解。

### Task 6: 队列与解锁
- 到期卡按 `dueAt` 升序排在新卡前；新卡按主线轮转、优先补最落后的线。
- **空章节（还没写卡）视为"已满足"，不挡解锁，但不出现在地图上。**

### Task 7: 持久化
- zustand + persist，IndexedDB（无 `indexedDB` 时回落 localStorage）。
- 导入 = 整包覆盖；`version` 必须为 1；坏文件只报错不动数据。

### Task 8–9: 设计系统与插画
- 墨 `#241A3D` 3px 描边、无模糊实心投影、`rounded-blob`。
- 小芯四种状态：idle / happy / confused / sleep。

### Task 10–14: 四个页面
- 学习台、卡片流（讲解面 → 问题面 → 反馈）、章节地图、记忆图谱、设置。

### Task 15: PWA
- `vite-plugin-pwa` autoUpdate，预缓存 11 个资源；图标由脚本栅格化生成（192/512）。

### Task 16: 收尾

## 评审与修复（2026-11-04）

独立评审提了 2 个 Critical、4 个 Important。处理如下：

### 已修（都有先失败后通过的测试）

- **C1 新卡首答跳空三天**：`review()` 改为第一次答对停在第 1 档（第二天复习），之后才逐档上升。原先新卡答对直接进第 2 档 = 3 天后，导致第二天、第三天打开都是"今天没事了"，连胜永远断开。
- **C2 断签不清零只写在磁盘上**：首页与结算页渲染时调用 `resolveStreak`，界面立刻显示 0。
- **I2 导入没有确认与备份，文案却说有**：改成两步（选文件 → 预览"将导入 X 张 / 覆盖本地 Y 张" → 确认后才写库），确认时先自动下载备份；`parseState` 增加对每条进度记录的字段校验（`box` 必须是 1–5、`dueAt` 必须是有限数字、`cardId` 必须是字符串）。
- **I3 答错的卡永远滞留在今日队列**：同一张卡当天答错 2 次后，`dueAt` 排到明天零点，首页才可能真正出现"今天没事了"。

### 裁定不改

- **I1 首发有 3 张卡被章节锁挡着**（指针、字节、XSS）：章节锁是设计要求（前一章全部记牢才解锁下一章），不是缺陷。代价：首发只有 5 张卡能立刻学，其余约第 10 天随解锁出现。已写入 README。
- **I4 IndexedDB 读写失败仍静默**：无痕模式或配额写满时会丢进度，没有错误提示。代价：用户可能不知道数据没存上；缓解手段是设置页的手动导出。留到 V2 加检测与横幅。
- **`<Link>` 包 `<Button>`** 产生的 `<a><button>` 嵌套：保留现状，等设计系统重构时一起处理。

## 内容与图解扩建（2026-11-05）

目标：把 8 张样板卡补到 80 张，并让每个知识点都有贴切的图，讲解从"一张静态图"变成"一步步点亮"。

### 做了什么

- **模型**：`Card` 新增 `steps: TeachStep[]`（`caption` + `focus`），每张卡 2–4 步。
- **图解系统**：新增 `src/illustrations/base.tsx`，提供 `Part`（按 focus 淡出未聚焦部分）、`Label`、`Box`、`Arrow`、`Defines` 与统一色板。
- **20 张章节概念图**：每章一张总览图，含 4 个语义化图元，正好对应本章 4 张卡。命名 `*Diagram.tsx`，各自导出 `*_PARTS`。
- **registry 改造**：从 `Record<string, Component>` 改为 `Record<string, { Component, parts }>`，新增 `getDiagramParts` / `hasIllustration` / `ILLUSTRATION_KEYS`。
- **讲解面**：StudyPage 讲解阶段按 steps 推进，图中只亮当前部分，配旁白 + 步骤点 + `1/3` 计数，最后一步才变成"懂了，考考我"。带 `aria-live="polite"` 播报旁白。
- **内容**：四条主线各 20 张，共 80 张；每章 4 张。原有 8 张卡的 id 全部保留（进度数据兼容），只补 `steps` 并换用新图。

### 关键决策

- **一章一图，四元聚焦**：不给 80 张卡各画一张图（重复且难维护），而是每章画一张"知识地图"，章内 4 张卡分别点亮不同区块。好处是 4 张卡之间形成结构关系，复习时能回忆"这张图里它在哪一块"。
- **focus 强制校验**：`content.test.ts` 检查每张卡 `steps[].focus` 必须是该插画 `parts` 的子集，写错图元 id 直接测试失败，避免高亮静默失效。
- **`Part` 用 style 而非属性控制 opacity**：SVG 属性变化不触发 CSS transition，用 `style` 才能得到 240ms 淡出过渡。
- **删除旧插画**（`Pointer/Binary/Process/Hash`）：内容全部改指向新图，旧文件无引用后移除，避免两套图并存。
- **截图核对**：临时加 `__gallery` 路由 + Playwright 把 20 张图渲染出来逐张看，修掉了缺页两行重叠、证书标签出画布、越权弧线穿框、闭包说明压边框等排版问题，完成后删除临时页与脚本。

### 测试

- `npm test`：15 文件 / **61 用例全绿**。新增用例覆盖：80 张总量、每章 4 张、steps 至少两步且旁白 ≤ 44 字、插画 key 已注册、focus 图元真实存在、每个图能带 focus 渲染。
- `npm run build` 通过。

## 桌面端导航补齐（2026-11-05）

**问题**：`BottomNav` 是 `md:hidden`，但桌面端没有替代导航。结果在电脑上打开只能看到首页，地图/图谱/设置三个页面完全没有入口。

**修复**：
- 新增 `src/components/navItems.ts`，把导航项与「当前 tab」的判断抽出来，顶部栏和底部栏共用。
- 新增 `TopNav.tsx`：`sticky top-0` 胶囊导航，`hidden md:block`，学习页（`/study`）不渲染，避免打断答题。
- `BottomNav` 改用共享配置，移动端行为不变。
- 首页 `h1` 在桌面端改为 `md:sr-only`：桌面品牌名由顶部栏承担，移动端仍显示大标题，语义与可访问性都保留。
- 测试补了三条：顶部导航按路径高亮、学习页不显示导航、App 提供四个入口。测试 61 → 64。

## 二、P1 · 设计文档欠账

### 1. 图谱页按主线分组的卡片下钻 ⬜ 下一项

**背景**：设计文档 5.4 要求「按主线分组的列表：每条线下钻到具体卡片，显示下次复习时间」，目前 `/stats` 只有 `learned/total` 和一个最近到期日，**没有卡片级视图**。

**做什么**

- 每条主线一个可折叠区块，展开后列出该线 20 张卡：状态色点 + 卡片标题 + 下次复习日期（`M 月 D 日`，未开始则写「还没开始」）。
- 默认只展开「快忘了 / 刚学会」最多的一条线，其余收起，避免一屏 80 行。
- 抽一个 `CardRow` 组件：薄弱卡入口与后续的错题本列表都复用它。
- 状态色点沿用图谱页现有的四色（记牢了 / 刚学会 / 快忘了 / 没学过），不要另起一套。

**验收**：图谱页能逐条看到 80 张卡各自的状态与下次复习时间；折叠/展开状态在切页后不丢失。

### 2. 首页四条主线可点 ⬜

**背景**：`HomePage` 的四条主线卡片现在是死的，点不动。

**做什么**

- 包一层 `<Link to="/map">`，hover 反馈直接复用章节节点那套（抬升 + 浅紫底）。
- 点进去后地图页要不要自动定位到对应主线？简单做法是不定位，只回地图；定位要加锚点参数，收益不大。

**验收**：四条主线都能点进地图。

## 三、P2 · 内容

### 3. 内容审校（需要你本人过一遍）⬜

只改 `src/content/tracks/*.ts` 与 `src/content/details/*.ts`，不动代码。按风险从高到低：

| 位置 | 要核对的点 |
|---|---|
| `hw-binary-03` | 8 位补码里 -128 = 1000 0000，对它取绝对值仍是负数 |
| `hw-binary-04` | 常用汉字 UTF-8 占 3 字节，GBK 占 2 字节 |
| `sec-tls-02` | TLS 1.3 握手是 1-RTT，0-RTT 有重放风险、只适合幂等请求 |
| `sec-auth-03` | RBAC 表达不了数据级权限，要叠加 ABAC 或查询条件 |
| `hw-network-02` | 实时音视频走 UDP 的理由是延迟优先，不是"UDP 更快" |
| `os-perm-01` | 对目录而言 `r` = 列出、`x` = 进入，两者含义不同 |

### 4. 内容扩容（可选，等数据说话）⬜

80 → 120 张有两条路，先看图谱数据再定：

- **加深**：每条线加一章（硬件加「存储层级」、安全加「供应链安全」等），保持 4 卡/章 → 100 张。
- **加线**：新增「数据库」「前端」两条主线，各 5 章 20 卡 → 120 张。工作量大，要配套两张新的章节概念图。

判断依据：等 30 天图谱出来，看哪条线的卡最先到期、错误率最高，就先扩哪条。
